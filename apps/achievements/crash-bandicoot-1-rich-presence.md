# Crash Bandicoot 1 — Rich Presence

> **Addresses:** `apps/games/code-notes/crash-bandicoot-1.md`; level ids, title screens and game states from
> the **wurlyfox/c1** decompilation of Crash Bandicoot, <https://github.com/wurlyfox/c1> (`src/common.h`
> `LID_*`, `src/globals.h`, `src/title.c`, `src/pbak.c`, `src/main.c`).
> **Script format:** `ra-developer-docs/rich-presence.md` in this directory.
> **Validated** in the headless harness (`tools/achievement-harness/`) against `SCUS-94900 — Crash Bandicoot
> (USA)`; see **Validation**.

The script the emulator evaluates to tell the site what the player is doing, e.g. `In N. Sanity Beach · 4 lives ·
23 Wumpa`. The strings are game data, in English, like RetroAchievements' own.

## Seeding

`python manage.py seed_crash1_rich_presence` is idempotent: it gets or creates the Crash game (and its disc
hash, like the other Crash seed commands) and stores the script in `Game.rich_presence_patch`, replacing any
other script; a current one is left alone. The server serves it as `RichPresencePatch` in `patch`.

The script is generated by `build_rich_presence()` in the command, from its tables of level names, boss fights
and bonus rounds.

## What it shows

The first line whose condition holds is shown, in this order:

| Condition | Shows |
| --- | --- |
| level id `0x6188d` is `00` (RAM before the first level loads) | `Starting up` |
| title level `19` and title screen `0x618d4` is `0f` | `On the island map` |
| title level `19`, by title screen: `05` main menu, `06` options, `0d`/`0e` password and load game; `0c` game over; anything else (the Sony, Universal and Naughty Dog screens) | `At the title screen` · `Game Over` · `Starting up` |
| level `2d` | `On the Stage Clear screen` |
| level `38` / `39` | `Watching the intro` / `Watching the ending` |
| demo playback `0x61a30` non-zero, or game state `0x618d1` is `06` | `Watching a demo of <level>` |
| game state `0x618d1` is `02` (from the last fatal hit until the title level loads) | `Game Over` |
| a boss fight (`08` Pinstripe, `0a` Papu Papu, `17` Ripper Roo, `1b` Dr. Nitrus Brio, `1f` Dr. Neo Cortex, `21` Koala Kong) | `Fighting <boss> · <n> lives` |
| any other level (the 27 stages and the Tawna, Brio and Cortex bonus rounds) | `In <level> · <n> lives · <n> Wumpa` |

`1 life` is singular. An unknown level id reads `an unknown level`; the retail game never loads one.

| Value | Read |
| --- | --- |
| Lives | the player object's lives: `I:0xW566b4_M:0xH165` (24.8 at `+0x164`) |
| Wumpa | the Wumpa HUD object: `I:0xW618a4_I:0xW6c_I:0xWe4_M:0xHc` |

Both objects hold leftovers of the previous level for up to about 20 frames after a level loads (`120 lives`,
`144 Wumpa` were measured), so the counts show only once the level id has held for 60 frames
(`R:0xH6188d!=d0xH6188d_0xH6188d=0xH6188d.60.`); until then the line is `In <level>` or `Fighting <boss>`. The
count restarts on a game load or a reset; a save state carries the runtime's hit counts, so loading one
restores them, unless the state was saved under another script. The player object is freed from a pause → quit,
and about 70 frames before the Stage Clear screen, until the level changes: its pointer then reads `0` and the
lives would come from address `0x165` (`0 lives`), so the counts also need `0xW566b4!=0`. The Wumpa HUD pointer
reads `0` until the first stage after power-on loads, so the Wumpa line also needs `0xW618a4!=0`. The committed
copies at `0x618ed` / `0x618f5` are not used: they only change on stage entry and exit.

The demo's playback flag `0x61a30` clears about 18 frames before a demo hands back to the title level, but the
game state reads `06` (`GAME_STATE_TITLE`, only ever seen in the attract loop) from before that point, so the
demo line holds to the end.

## Validation

**Syntax:** `scripts/check-mem-addr.sh` takes a whole script (any argument with a line break or a `Display:`
section) and parses it with the vendored `rc_richpresence_size`; it also fails on a macro that names no
`Lookup`, `Format` or built-in, which the parser accepts and the emulator displays as `[Unknown macro]`.
`pytest` runs it over the seeded script.

**Behaviour:** every harness scenario runs with the script active in the vendored rcheevos runtime, evaluated
after every frame (`rc_runtime_get_richpresence`), and fails when a string it expects never shows or when any
string shows `[Unknown macro]` or `an unknown level`; the deaths, quit, clear and boss scenarios, which never
reach the last life, also fail on `0 lives`. Runs on `PCSX-ReARMed r26 ff81ed1` with rcheevos 12.3.

| Scenario | Strings shown, in order (frame) |
| --- | --- |
| `cold-boot`, `attract` | `Starting up` (1) → `At the title screen` (1791) → `Watching the intro` (4130) → `At the title screen` → `Watching a demo of Jungle Rollers` (8266) → `At the title screen` (11433, as the title level loads) → … `The Great Gate`, `Boulders`, `Papu Papu`, `The Lost City`, `Jaws of Darkness`, `The Lab`, the intro again |
| `game-over` | `In N. Sanity Beach` → `In N. Sanity Beach · 4 lives · 0 Wumpa` (frame 61) → `3 lives · 8 Wumpa` → `2 lives` → `1 life` → `0 lives · 14 Wumpa` → … `24 Wumpa` → `Game Over`, held from the fatal hit through the game over screen |
| `<stage>-deaths`, six stages | `In <stage> · 4 lives · 0 Wumpa`, then one life less on each fatal hit, e.g. `In Upstream · 3 lives · 1 Wumpa` → `2 lives · 2 Wumpa` → `1 life · 2 Wumpa` |
| `<stage>-quit`, six stages | `In <stage> · 4 lives · …` → `In <stage>` from the quit (player object freed) → `On the island map` → `In <stage>` for 60 frames on entry → `In <stage> · 4 lives · 0 Wumpa` → … |
| `<stage>-clear` | `In N. Sanity Beach · … 20 Wumpa` → `In N. Sanity Beach` (7057) → `On the Stage Clear screen` (7127, the achievement's frame) → `On the island map` → `In Jungle Rollers · 4 lives · 20 Wumpa` → `On the island map` |
| `papu-papu-quit` | `Fighting Papu Papu` → `Fighting Papu Papu · 4 lives` → `Fighting Papu Papu` from the quit → `On the island map` |

`attract-then-new-game` sits through the first demo, then starts a new game: `Watching a demo of Jungle
Rollers` → `At the title screen` (11433) → `On the island map` (11814) → `In N. Sanity Beach` (12561) →
`In N. Sanity Beach · 4 lives · 0 Wumpa` (12621), never `Watching a demo of N. Sanity Beach`, so the attract
game state does not leak into play.

### Still for the in-game check (DuckStation)

- **The site shows the string DuckStation pings**, every two minutes, on the user's page: the harness reads the
  runtime directly and never goes through `ping`.
- **Bonus rounds** (`In a Tawna bonus round · …`, Brio, Cortex): the harness never collected three tokens. Their
  level ids (`24`, `33` Tawna, `25` Brio, `34` Cortex) are c1's, not measured.
- **Stages and bosses the harness never entered**: every name but the six level-achievement stages, the demo
  stages (The Lost City, Jaws of Darkness, The Lab) and Papu Papu comes from c1's `LID_*` table. So does the
  ending (`39`), never reached.
- **Loading a memory card save or a password** (title screens `0d`/`0e`) and the options screen: never opened.
- **Lives above 9 and Wumpa rolling over at 100**: never reached.
- **The Wumpa chain's inner hops** (`+0x6c`, `+0xe4`): only the HUD pointer itself is guarded; no trace showed
  the counts with a null inner hop.
